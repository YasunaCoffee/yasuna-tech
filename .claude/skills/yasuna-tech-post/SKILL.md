# yasuna-tech 記事執筆スキル

yasuna のテックブログ（Deno + Lume）に、**yasuna 文体**で記事を書くためのスキル。

作業はリポジトリのルートで行う。運用全体と落とし穴は `AGENTS.md` にある。
手元に無ければ `git clone https://github.com/YasunaCoffee/yasuna-tech.git`。

## 手順

### 1. テーマを確認する

ユーザーから **テーマ・狙い・公開予定日** を確認する。ユーザーの実体験と矛盾する事実は捏造しない。不明点は質問する。

### 2. 文体を読み込む

**必ず実行時に `prompts/yasuna-style-prompt.md` を読む**（このスキルに文体を複製しない＝単一ソースを保つ）。要点:

- 基本は **です・ます**。感情には「！」や軽い口語を少量。自己開示は率直に、上から目線は避ける。
- 冒頭は状況を短く宣言（`結論、` など。「端的に言うと」は使わない）。`# はじめに` / `# まとめ` を使う。
- 強調は **太字** を少しだけ。`ちなみに`（脱線）/ `そこで`・`また`（話題転換）。
- 外部リンクは URL を行でそのまま置くことも多い。
- タイトルに Noto Sans JP で出ない文字（`――` 等）を使わない。区切りは `：`。
- **`category: "論文読んでみた"` の記事**は、同ファイルの専用ルールに従う（論文パートと自分パートを `---` で分離、論文に書いていないことを書かない、AITuber 文脈に紐付け、VTuber と混同しない）。

### 3. フロントマターを付ける

**`templates/post.md` をコピーして起こす**（フロントマターと見出し構成の雛形が入っている。
このスキルに複製しない＝単一ソースを保つ）。ファイル名・スラッグは **kebab-case**
（`foo-bar.md` → `/posts/foo-bar/`）。

雛形の値を差し替えるときの注意は `AGENTS.md` の「落とし穴」を見る（`emoji` はサムネにも使う、
`category` 省略時の挙動、タイトルに使えない文字、`:::message` が効かないこと）。

### 3.5. 外部リンクをカードで並べる（任意）

言語指定を `linkcard` にしたフェンスに、URL を1行1つ。複数行ならグリッドになる。

````markdown
```linkcard
https://muilab.com/
https://remarkable.com/
```
````

画像はリンク先の OGP を**ホットリンク**する（転載しない）。URL を足したら
`deno task linkcards` でキャッシュを更新してからコミットする（`yasuna-tech-build` スキル）。

### 4. 保存先を選ぶ

- **まだ公開しない** → `drafts/{slug}.md`（ビルド対象外）。
- **公開する** → `src/posts/{slug}.md`。ユーザー指示がない限り、公開用は `src/posts/` のみ触る。

### 5. 実績に載せる場合（任意）

その記事を **2026 年の実績**に載せたいときは、同じ作業のなかで `src/posts/jisseki-2026.md` を更新する。手順は `.cursor/skills/jisseki-2026-update/SKILL.md` に従う（新しい番号セクション追加、冒頭の件数更新、一覧表に行追加）。「実績に載せない」と言われた記事は対象外。

### 6. 確認

プレビュー・ビルドが必要なら **`yasuna-tech-build` スキル**を使う（`deno task dev` でサムネ生成込みプレビュー）。

## 記事の長さ

**内容に見合った長さにする。** 短くすることが目的ではなく、体験や所感を削る必要はない。
ただし埋め草セクション・同内容の要約の繰り返し・「まとめ」の水増しで量を稼がない。
書くことが尽きたらそこで終わる。

## やらないこと

- `_site/` を手で編集しない（ビルド成果物）。
- 文体プロンプトにない別ペルソナに勝手に切り替えない。
- 根拠のない大言壮語・「いかがでしたか」の連発・誹謗中傷。
